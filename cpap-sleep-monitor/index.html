CPAP Sleep Monitor

complete

A CPAP machine holds a sleeping patient's airway open by pushing air at a set pressure. Too low and the airway still collapses; too high and the patient stops tolerating the mask and quits using it altogether. Somebody has to look at how a person is actually breathing and adjust the number.

We built for a ward rather than for a device: several bedside monitors, and staff who need to see all of them at once. A nurse updates a patient's details at the bedside. A doctor at a central station pulls up any active room, reads the most recent session, pages back through earlier tests and changes the prescribed pressure without walking down the hall.

That shape drove the architecture into two Flask applications instead of one. A REST API server owns the database and every piece of domain logic; a GUI client renders HTML and holds no data of its own. The bedside screen and the central station are then the same client code against the same API — there is no way for the two views to disagree about a patient, and the analysis and storage layers can be tested without a browser anywhere near them.

Serving HTML rather than shipping a desktop app was a deliberate call about hospitals: nobody wants to install and update software on every bedside machine in the building. A browser is already there. A fix means updating one server instead of touching every room.

The data model is Room → Patient → Results in MongoDB, and the part that matters clinically is that a patient is keyed by medical record number, not by where they are sleeping. Rooms are places people pass through. Results are embedded in the patient, so "show me this patient's history" — the query the monitoring station makes constantly — is a single read.

The analysis is where the real work sits. Input is a raw text file from a Venturi flow meter, still in ADC counts. Calibrate to cmH₂O; convert pressure drop across the constriction into volumetric flow via Bernoulli; compare the inspiratory and expiratory taps to get direction, so inhale reads positive and exhale negative; smooth by moving average, because raw flow is far too noisy to peak-detect against.

Then count breaths, which is the fiddly part. A stock peak finder over-reports — one breath can present as a double hump and get counted twice — so there is a validation pass that checks whether the signal really returns to baseline either side of a candidate, and compares neighbouring peaks where it does not. Getting that right is the difference between a plausible number and a correct one. Apnea events are gaps of ten seconds or more between breaths, which is the standard clinical threshold.

Bad input is logged rather than fatal: short rows, non-numeric fields and NaNs are caught, counted by line number and skipped. Negative leakage raises a warning, because it means something upstream is wrong.

Unit tests across all three modules, with GitHub Actions running pytest and pycodestyle on every push.

What we did not finish, since this archive is honest about that: at the deadline the patient-side auto-refresh was not working, and rendering historical plots from a selected timestamp landed after the cutoff. The core loop — record, analyse, store, retrieve, adjust — worked end to end on a real VM. It was a course project that ran out of clock, not a product. There is a demo video of it running.
