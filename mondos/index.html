Mondo's

in progress

A marketing site for a bar and grill: menu, Greek Night, and an About page. Still in progress, and the longest-running project in this archive.

Architecturally it is static, aggressively so. React Router in framework mode with server-side rendering off and prerendering on, which emits a real HTML file per route at build time. No server, no database in production — the build output goes to S3 and is served through CloudFront.

The most interesting artefact in the repository is an architecture decision record titled what this project deliberately does not build. The original plan had Spring Boot, JPA, an Aurora database and an admin UI so the owner could edit his own menu. Costed out honestly, that came to somewhere between fifteen and ninety dollars a month — load balancer, NAT gateway, a database instance billed around the clock — against roughly one or two dollars for static files on S3 and CloudFront.

The reasoning that killed it is the part worth keeping: a four-category menu of flat records is content, not data. No relationships, no transactions, no concurrent writers, nothing to tune. The JPA learning goal was real, and the document says so, then parks it on a future project whose modelling is actually relational instead of bending this one to fit. Writing down why you did not build something — so it does not get re-proposed a year later as an obvious improvement — turned out to be one of the more useful things I have done on a project.

The visual brief was neon, because the restaurant is known for its sign. That produced findings I did not expect. You cannot make hollow neon with text-shadow: it always renders a filled glyph with a halo, and a hollow tube needs a text stroke with transparent fill plus chained drop-shadow filters that follow the stroke's alpha. Every character has to be its own element, because a raster logo cannot do per-glyph failure — which is why the wordmark is live text. Only letters are allowed to fail alone; a lone apostrophe blinking reads as a bug rather than a dying tube. And the dropout timing was tuned by ear: out, catch, out, one last flicker, give up, about three seconds cold, then relight badly before settling. The long dark hold is the effect.

The menu is a grid of cards that flip in place — photo and price on the front, description and add-ons on the back over a dimmed copy of the same image. The card never moves or resizes, and the aspect ratio is locked so the grid cannot reflow mid-flip.

The lesson from the whole build, lifted from my own notes: two traps found by rendering, not reasoning. Glow bridging fine detail, and a scrim implemented as a pseudo-element breaking absolute positioning in sibling elements — which is exactly how the price kept jumping out of its corner. Neither was predictable on paper.
